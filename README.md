# dmu80pCreoHeidenhain

Конвертер **Creo / ProE CL** (`.ncl` / `.ncl.1`) → **Heidenhain Klartext** (`.h`)  
для верстата **DMU 80P**, стійка **TNC 426/430**.

Це **не** офіційний постпроцесор DMG. Цеховий профіль під локальні правила:  
M54/M53, СОЖ `M3 M8` / `M5 M9`, Q339=3, LBL, футер WORKING PLANE, ім’я програми ≤ 8 латиниця.

---

## Що потрібно

| Що | Навіщо |
|----|--------|
| **Python 3.12+** (перевірено на 3.13) | Запуск `convert.py` |
| Файли CL з Creo/ProE | Вхід `.ncl` / `.ncl.1` |

Сторонніх пакетів pip **немає** — лише стандартна бібліотека Python.

Перевірка:

```powershell
python --version
```

Має бути на кшталт `Python 3.13.x`. Якщо бачите лише слово `Python` або шлях у `WindowsApps` — це заглушка Store; поставте Python з [python.org](https://www.python.org/downloads/) з галочкою **Add python.exe to PATH**.

## Структура проєкту

```text
dmu80pCreoHeidenhain/
├── convert.py          # конвертер (CLI)
├── machines/
│   ├── __init__.py
│   └── dmu80p.py       # профіль верстата (M-коди, Q339, зміщення M53…)
├── ncl/                # вхідні CL з Creo
├── h/                  # вихідні .h (створюється/дописується автоматично)
├── etalon/             # еталонні цехові .h для порівняння
└── tests/
    └── test_machine.py # перевірка профілю (Q339=3 тощо)
```

| Папка / файл | Роль |
|--------------|------|
| `ncl\` | Кладете сюди `.ncl.1` з Creo |
| `h\` | Сюди пишеться результат `.h` |
| `etalon\` | Ручні/цехові еталони (для звірки очима) |
| `machines\dmu80p.py` | Усі цехові константи в одному місці |

Пошук вхідного файлу, якщо вказали лише ім’я:  
абсолютний шлях → `ncl\<ім’я>` → поточна папка.

## Швидкий старт

Відкрийте PowerShell у папці проєкту:

```powershell
cd C:\Users\admin\Desktop\dmu80pCreoHeidenhain\dmu80pCreoHeidenhain

# усі .ncl / .ncl.1 з ncl\ (і дублікати з поточної папки) → h\
python convert.py

# один файл з ncl\
python convert.py 777.ncl.1

# явно: вхід, вихід, ім’я програми, нуль
python convert.py ncl\2yst3.ncl.1 -o h\2yst3.h --name 2YST3 --q339 3

# уся папка
python convert.py --dir .\ncl

# дуги в стилі CR замість CC/CP
python convert.py ncl\2yst3.ncl.1 --cr -o h\2yst3.h

# перевірка готового .h
python convert.py --check h\777.h

# з номерами кадрів
python convert.py --numbers 777.ncl.1
```

Після успіху в консолі буде щось на кшталт:

```text
CHECK: OK (523 lines)
OK: ...\h\777.h
MACHINE: DMU 80P / TNC 426/430
PGM: 777
HEAD: M54 vertical
ARCS: CC/CP
Lines: 523
```

## Опції командного рядка

| Опція | Що робить |
|-------|-----------|
| `<file.ncl.1>` | Один вхідний CL-файл |
| `-o` / `--output` | Куди зберегти `.h` |
| `--name` | Ім’я `BEGIN PGM` / `END PGM` (≤ 8: A–Z, 0–9, `_`; кирилиця транслітерується) |
| `--dir <folder>` | Пакетно всі `.ncl` / `.ncl.1` у папці |
| `--q339 <n>` | Номер бази в `CYCL DEF 247` (за замовчуванням **3**) |
| `--numbers` | Номери кадрів: `0  BEGIN PGM …` |
| `--arcs cc` | Дуги **CC** + **CP** (за замовчуванням) |
| `--arcs cr` або `--cr` | Дуги **CR** (радіус) |
| `--no-cr` | Повернутись на CC/CP |
| `--check <file.h>` | Лише перевірити структуру Klartext |

Без аргументів — пакетна обробка файлів з `ncl\` і поточної директорії.

## Типовий процес у цеху

1. З Creo зберегти CL (`.ncl.1`) у папку `ncl\`.
2. У папці проєкту виконати `python convert.py` або вказати конкретний файл.
3. Відкрити `.h` з `h\` у редакторі / на стійці.
4. За потреби руками підправити: кишеню, компенсацію радіуса, Q339, DR/DL.
5. Перед верстатом — симуляція або суха прогонка.
6. За бажанням: `python convert.py --check h\….h`.

## Що робить конвертер (по кроках)

1. Читає CL (рядки з продовженням `$`).
2. Парсить команди та метадані з `PPRINT` (дата, операція, інструмент, діаметр…).
3. Визначає режим голови / площини:
   - **M54** — вертикальна голова (звичайний випадок)
   - **M53** — горизонтальна (вісь інструмента майже лежача, A≈90°)
   - **ручний переворот** (вектор k≈−1) — площина A0 C0, координати `(x, −y, −z)`, **без** A+180
4. Будує Klartext: заголовок, список інструментів, `LBL`, нуль/база, TOOL CALL, рухи, футер.
5. Пише файл у **CP1251**, рядки **CRLF**, у папку `h\`.
6. Ганяє структурну перевірку (`CHECK: OK` / `CHECK FAIL`).

### Підтримувані команди NCL

| Команда | Результат у `.h` |
|---------|------------------|
| `PARTNO`, `UNITS`, `PPRINT` | Метадані, коментарі інструмента |
| `MULTAX` | Мультиосьовий контекст |
| `LOADTL` | `TOOL CALL` (+ зміна інструмента через `LBL`) |
| `SPINDL` | Оберти `S…` |
| `RAPID` / `FEDRAT` | `F MAX` / робоча подача |
| `CUTCOM` LEFT/RIGHT/OFF | `RL` / `RR` / `R0` |
| `GOTO` XYZ або XYZ+IJK | Лінійні `L` |
| `CIRCLE` + наступний `GOTO` | Дуги `CC`/`CP` або `CR` |
| `FINI` | Кінець траєкторії |

Ігноруються / лише попередження: `FROM`, `COOLNT`, `MACHIN`, невідомі команди.  
**СОЖ з NCL не береться** — завжди цехові `M3 M8` / `M5 M9`.

### Режими площини

| Умова | Поведінка |
|-------|-----------|
| Вертикаль (M54), є нахил IJK | `CYCL DEF 19` з A/C; координати → робоча площина |
| Горизонталь (M53) | A≈0, C зі стола; зміщення Y+0.38 / Z−0.385 |
| Ручний переворот (k≈−1) | A0 C0; XYZ дзеркаляться `(x,−y,−z)` |

### Дуги

- **За замовчуванням:** центр `CC` + дуга `CP IPA… IZ… DR±`
- **`--cr`:** дуги `CR X… Y… R… DR±` (або X/Z для горизонтальної голови)

## Профіль верстата (`machines/dmu80p.py`)

| Параметр | Значення |
|----------|----------|
| Вертикальна голова | `M54 ;vertical head` |
| Горизонтальна голова | `M53 ;horizontal head` |
| Орієнтація шпинделя | `M126` |
| Машинні координати | `M91` |
| СОЖ увімк / вимк | `M3 M8` / `M5 M9` |
| Нуль Q339 | **3** (зміна: `--q339`) |
| Компенсація в TOOL CALL | `DR+0.0 DL+0.0` |
| Кінець інструмента / програми | `M1` між інструментами, `M30` в кінці |
| Кінцевий TOOL CALL | `TOOL CALL Z S1000` |
| Ім’я програми | ≤ 8 латиниця |
| M53 зміщення | Y+0.38, Z−0.385 |

Щоб змінити дефолти для всього цеху — редагуйте `machines/dmu80p.py`.

## Як виглядає вихід

- Кодування: **Windows-1251 (CP1251)**
- Кінець рядка: **CRLF**
- Шлях за замовчуванням: `h\<ім’я_входу>.h`
- Числа в стилі Heidenhain: `Y+.776` (без зайвого `0` перед крапкою)

Фрагмент реальної шапки:

```text
BEGIN PGM 777 MM
;DATE : 23-NOV-26 13:48:46
;MACHINE : DMU 80P
;OP020
;T003  : FLAT D=8 L=100 FLUTE=-1 (FR8CHERN)
;T004  : FLAT D=8 L=100 FLUTE=-1 (FR8CHIST)
LBL 1 ; FR8CHERN
CYCL DEF 7.0 DATUM SHIFT
…
CYCL DEF 247 DATUM SETTING ~
    Q339=3   ;DATUM NUMBER
CYCL DEF 19.0 PLOSKOST OBRABOTKI
CYCL DEF 19.1 A+0. C+0. F AUTO SET UP 10
…
TOOL CALL 3 Z S5968 DR+0.0 DL+0.0
L Z-1 F MAX M91
M3 M8
M126
M54 ;vertical head
…
CC X54 Y-7
CP IPA+180 IZ+0 DR+
```

Кілька інструментів у одному CL → кілька `LBL` з повторною шапкою нуля/бази між ними.

## Перевірка `.h`

```powershell
python convert.py --check h\777.h
```

Контролює:

- наявність `BEGIN PGM` / `END PGM`
- наявність `TOOL CALL`
- наявність `M1` або `M30`
- послідовність номерів кадрів (якщо вони є)

Це **структурна** перевірка, не геометрія і не симуляція верстата.

## Обмеження

- Одна площина орієнтації на програму (зміна A/C посередині — попередження).
- Не повний 5-осьовий simultaneous пост: орієнтація через CYCL 19 + ходи в площині.
- Дуги потребують пари `CIRCLE` → `GOTO`.
- Кілька `LOADTL` підтримуються через `LBL`, але результат варто звірити з еталоном.
- Перед запуском на верстаті обов’язкова перевірка оператором.

## Поширені проблеми

| Проблема | Що зробити |
|----------|------------|
| `python` не знайдено / лише `WindowsApps` | Встановити Python з python.org + PATH; вимкнути App execution aliases |
| `Немає .ncl / .ncl.1` | Покласти файли в `ncl\` або вказати шлях явно |
| `File not found` | Перевірити ім’я / покласти файл у `ncl\` |
| Кирилиця в імені програми | Автоматично транслітерується і обрізається до 8 символів; краще задати `--name` |
| Дуги «не як на стійці» | Спробувати `--cr` або залишити CC/CP (дефолт) |
| Нужна інша база | `--q339 4` або змінити дефолт у `machines\dmu80p.py` |
| Файл «кракозябрами» в Notepad++ | Відкрити як **Windows-1251 (CP1251)** |
